# 윷놀이 게임 페이지 설계

## 배경

추석 전 사무실에서 간단히 즐길 수 있는 윷놀이 페이지가 필요하다. 기존 계산기 사이트와는 완전히 다른 성격의 콘텐츠라 사이트 메뉴/사이드바/검색/SEO에는 노출하지 않고 URL로만 접근 가능한 숨김 페이지로 만든다. 1회성 오프라인 이벤트용이라 로그인·저장·다중 기기 동기화는 필요 없다.

## 목표

`/yutnori` URL로 접근하는 새 페이지를 추가한다. 팀 구성(2~4팀, 팀당 1~5명) → 말 색 자동 배정(빨/파/노/초) → 정통 윷놀이 보드(대각선 지름길 포함) → 팀별 턴 진행(업힘/잡기/백도/추가턴 포함) → 순위 결정(전체 완주 또는 시간제한)까지 한 화면(기기 1대)에서 진행한다.

## 라우팅 & 노출 제어

- `src/routes.json`에 항목 추가:
  ```json
  {
    "id": "yutnori",
    "path": "/yutnori",
    "label": "윷놀이",
    "group": "게임",
    "title": "윷놀이 | 계산기",
    "description": "사무실에서 즐기는 온라인 윷놀이. 팀을 만들고 윷 던진 결과만 입력하면 보드와 말이 자동으로 움직입니다.",
    "noindex": true
  }
  ```
  `"게임"`은 `src/groups.json`(GROUP_ORDER)에 없는 그룹이다. `App.tsx`·`Sidebar.tsx` 모두 `groups = GROUP_ORDER.filter((g) => routes.some(...))`로 표시 그룹을 계산하므로, GROUP_ORDER에 없는 그룹은 사이드바·모바일 메뉴·사이드바 검색 어디에도 나타나지 않는다(기존 로직 재사용, 코드 수정 불필요). 푸터는 `group === '정보'`만 출력하므로 여기도 자동 제외. `noindex: true`로 `postbuild.mjs`의 sitemap.xml/robots meta에서도 제외된다.
- `src/App.tsx`의 `components` 레지스트리에 `yutnori: lazy(() => import('./pages/YutnoriGame'))` 추가.
- `src/lib/pageContent.js`에는 `yutnori` 항목을 추가하지 않는다 → `InfoSection`이 `if (!c || c.hidden) return null`로 자동 스킵.
- `App.tsx`에서 광고(AdSlot) 렌더링 조건에 `route.id !== 'yutnori'`를 추가해 이 페이지에서는 광고를 띄우지 않는다(사무실용 게임 페이지에 광고가 뜨는 건 어색하고, AdSense 저품질 반려 이력도 있어 관련 없는 페이지에 광고를 노출하지 않는 게 안전하다).

## 보드 모델 (`src/lib/yutnori.ts`)

정통 윷놀이판을 그래프(노드 + 다음 노드 맵)로 표현한다.

- **바깥 테두리**: 20칸(모서리 4개 + 각 변 4칸씩). 팀은 최대 4개이므로 팀마다 서로 다른 모서리에서 출발(표준 3~4인용 윷놀이 방식으로 혼잡 방지), 진행 방향은 전 팀 동일(반시계 방향).
- **지름길**: 각 모서리에서 중앙(방)을 거쳐 대각선 반대편 모서리로 가는 경로 2개. 한 말이 지름길에 진입할 수 있는 시점은 "자신이 그 모서리를 정확히 밟았을 때"이며, 이미 지름길을 한 번 탄 말은 이후 남은 지름길 분기 없이 최단경로로 도착점까지 직행한다(전통 규칙).
- **완주**: 도착점을 넘어서면 완주 처리(정확히 맞을 필요 없음), 해당 말은 보드에서 제거되고 팀의 완주 말 수에 반영된다.

핵심 함수:
```ts
export type ThrowResult = 'do' | 'gae' | 'geol' | 'yut' | 'mo' | 'baekdo' // 도/개/걸/윷/모/백도

export interface Piece {
  id: string       // `${teamId}-${pieceIndex}`
  teamId: number
  position: number | 'home' | 'finished' // 보드 노드 id | 대기 상태 | 완주
  path: number[]    // 지금까지 밟아온 노드 경로 (지름길 재진입 판단용)
}

export function stepsFor(result: ThrowResult): number // 도1 개2 걸3 윷4 모5 백도-1
export function grantsExtraTurn(result: ThrowResult): boolean // 윷/모
export function movePiece(board: Board, piece: Piece, steps: number): Piece // 지름길 반영 이동
export function resolveLanding(pieces: Piece[], movedPiece: Piece):
  { merged: Piece[]; captured: Piece[]; extraTurn: boolean } // 업힘/잡기 판정
```

- **업힘**: 이동 후 같은 팀 말이 있는 칸이면 두 말을 하나의 그룹(같은 `position`, 그룹 이동 단위)으로 합친다. 합쳐진 말은 이후 항상 함께 이동하며 다시 분리되지 않는다.
- **잡기**: 이동 후 상대 팀 말이 있는 칸이면 그 칸의 상대 팀 말 전부(업힌 그룹 포함)를 `position: 'home'`으로 되돌리고, 잡은 팀에게 추가 턴을 준다.
- **백도**: 팀의 보드 위 말이 하나도 없으면(전부 `home`) 이동 불가 — UI에서 "이동할 말 없음" 안내 후 자동으로 턴 종료 처리. 보드 위 말이 있으면 그 중 하나를 한 칸 후진시키되 시작 칸보다 더 뒤로는 가지 않는다(시작 칸에서 멈춤).

## 게임 진행 상태 (`src/pages/YutnoriGame.tsx`)

- **설정 화면**: 팀 수(2~4) → 팀별 인원 이름 입력(1~5명, 인원 수 = 그 팀 말 개수) → 팀 색 자동 배정(빨/파/노/초 순서) → 종료 모드 선택(① 전체 완주까지 진행 ② 시간제한 N분, 기본 10분) → "게임 시작".
- **진행 화면**: 팀 순서 라운드로빈 턴 표시 → 도/개/걸/윷/모/백도 버튼으로 결과 입력 → 이동 가능한 말(또는 업힌 그룹)이 여러 개면 선택 UI 표시 → `movePiece`/`resolveLanding` 적용 → 윷/모/잡기 시 같은 팀이 이어서 던지도록 턴 유지(추가 턴 카운트 표시), 아니면 다음 팀으로.
- **순위 처리**: 팀의 말이 모두 `finished`가 되면 그 팀의 순위를 확정하고 화면에 "N등 확정" 표시, 게임은 나머지 팀으로 계속 진행. 종료 모드가 "전체 완주"면 모든 팀 순위가 확정될 때까지 진행하고 최종 순위표를 보여준다. "시간제한"이면 타이머(설정한 N분)가 끝나는 시점에 완주 말 수(내림차순) → 동률이면 전체 말의 누적 이동 칸 수 합산(내림차순)으로 순위를 자동 산정해 최종 순위표를 보여준다.
- 상태는 전부 `useReducer` 기반 로컬 React state. 새로고침하면 초기화된다(백엔드/저장소 없음).

## 검증 계획

- `src/lib/yutnori.ts`는 분기가 많은 순수 함수라 테스트 프레임워크 없이 실행 가능한 assert 기반 자체 점검 스크립트를 함께 추가한다(예: 지름길 진입/재진입, 업힘 후 그룹 이동, 잡기로 인한 리셋, 백도 경계 처리, 완주 판정).
- 브라우저에서 실제로 2~4팀 시나리오를 플레이해 업힘·잡기·지름길·백도·시간제한 순위 산정이 화면상 기대대로 동작하는지 수동 확인한다.
- `npx tsc -b --noEmit`, `npm run build`, `npm run lint` 통과 확인.
- 빌드 후 `/yutnori` 페이지가 사이드바·모바일 메뉴·검색·푸터·sitemap.xml 어디에도 노출되지 않고, URL 직접 접근 시에는 정상 동작하는지 확인.

## 범위 제외

- 다중 기기 실시간 동기화(백엔드·소켓) — 한 화면 공유 플레이로 충분하다고 판단.
- 개인 계정/전적 저장 — 1회성 이벤트용, 새로고침 시 초기화되는 것을 전제로 한다.
- 윷 던지기 애니메이션/실제 난수 판정 — 사용자가 실제로 윷을 던지고 결과만 입력하는 방식이라 불필요.
