# 가이드 섹션 신설 — 설계 문서

## Context

계산기 콘텐츠 심화(2026-07-30, PR #1)로 AdSense 콘텐츠 품질 문제에 대응한 데 이어, SEO 트래픽 확대를 위해 계산기 도구 자체가 아닌 장문 아티클/가이드 콘텐츠 섹션을 신설한다. 이는 최초 콘텐츠 브레인스토밍에서 "4번(완전히 새로운 방향)"으로 미뤄뒀던 항목이자, 콘텐츠 심화 설계 문서의 "범위 밖" 2번 하위 프로젝트다.

## 콘텐츠 범위

첫 버전은 두 트랙, 총 8편으로 시작한다.

**트랙1 — 계산기 확장판 (4편)**: 기존 계산기와 자연스럽게 연결되는 절차·실무 가이드.
1. 2026년 연말정산 신고 절차 A to Z (→ 연말정산 환급액 계산기)
2. 전세보증금 못 받았을 때 대처법 (→ 전월세 전환율 계산기)
3. 퇴직금 중간정산 가능한 경우 정리 (→ 퇴직금 계산기)
4. 실업급여 신청 절차·준비서류 (→ 실업급여 계산기)

**트랙2 — 정부지원금/청년정책 (4편)**: 계산기와 무관한 완전 신규 주제.
1. 2026년 청년월세 지원 총정리
2. 청년도약계좌 가입조건·정부기여금·중도해지
3. 청년 전세자금대출(버팀목) 조건과 한도
4. 국민취업지원제도 구직촉진수당 신청 조건

## 아키텍처 — 기존 인프라 재사용

새 콘텐츠 타입을 위한 별도 CMS/마크다운 파이프라인을 만들지 않고, 계산기와 동일한 라우팅·렌더링·프리렌더 인프라를 그대로 재사용한다.

- **라우팅**: `src/routes.json`에 가이드 라우트 추가. 목록 페이지 `id: "guidesIndex"`, `path: "/guides"`. 개별 글은 `path: "/guides/<slug>"`. 모두 `group: "가이드"`.
- **사이드바 제외**: `src/groups.json`(좌측 아코디언 그룹 순서)에는 `"가이드"`를 추가하지 않는다. 기존 `"정보"` 그룹(소개/개인정보처리방침)과 동일하게, `App.tsx`/`Sidebar.tsx`의 `groups = GROUP_ORDER.filter(...)` 로직에 의해 좌측 사이드바 아코디언에는 자동으로 노출되지 않는다.
- **본문 저장**: 계산기와 동일하게 `src/lib/pageContent.js`에 저장한다. 새 스키마를 만들지 않고 기존 `PageInfo` 필드(`intro`/`glossary`/`faqs`/`sources`)를 그대로 쓴다 — `intro` 배열이 가이드 본문의 문단들이 되고, 트랙1처럼 절차형 콘텐츠는 `formula`(제목을 "이렇게 진행하세요" 류로 재해석) 필드로 단계별 절차를 표현한다.
- **렌더링**: `src/components/InfoSection.tsx`를 그대로 재사용 — 변경 없음. 공용 `src/components/GuideArticlePage.tsx`를 신설해 `<h1>{route.label}</h1>` + `<InfoSection pageId={pageId} />`만 렌더링한다.
- **페이지 컴포넌트**: 가이드마다 `src/pages/guides/<Name>Guide.tsx` 파일을 만들어 `GuideArticlePage`에 자기 `pageId`만 넘긴다(계산기 로직이 없으므로 페이지당 3~4줄).
- **목록 페이지**: `src/pages/GuidesIndexPage.tsx` — `routes.json`에서 `group === "가이드" && id !== "guidesIndex"`인 라우트를 필터링해 트랙별로 나눠 카드 목록으로 보여준다(AboutPage가 이미 `routes.json`을 직접 import하는 선례와 동일한 패턴).
- **프리렌더**: `scripts/postbuild.mjs`는 `pageContent[route.id]` 기반으로 이미 모든 라우트를 범용적으로 처리하므로 코드 변경이 필요 없다. 단, `GuidesIndexPage`는 정적 프리렌더에서 카드 목록(제목+설명+링크)이 보이도록 `prerenderBody`에 "가이드" 그룹 전용 분기를 하나 추가한다(현재 로직은 `pageContent[route.id]`만 렌더링하고 목록 페이지에는 그런 콘텐츠가 없으므로).

## 관련 계산기 링크 (트랙1 전용)

트랙1 가이드는 본문 끝에 "관련 계산기" 섹션을 붙인다. 사이트의 SPA 클라이언트 라우팅(`navigate` 함수)은 현재 `App.tsx` 내부 클로저라 하위 컴포넌트에 배선하려면 새 매커니즘(context 등)이 필요하다 — 이번 범위에서는 그 배선을 만들지 않고, 일반 `<a href="/경로/">` 링크(클릭 시 전체 페이지 새로고침)로 처리한다. 가이드→계산기 이동은 낮은 빈도의 1회성 전환이라 새로고침 비용이 크지 않다고 판단했다. `GuideArticlePage`가 아니라 각 가이드 페이지 파일에 `relatedCalculators: {label, path}[]` 배열을 지역 상수로 두고 렌더링한다(공용 스키마에 넣지 않아 계산기 쪽에 영향 없음).

## 네비게이션 노출

데스크톱 사이드바 상단(로고/태그라인 아래, 아코디언 위)과 모바일 상단바 메뉴 안에 "📖 가이드" 링크를 추가해 `/guides` 목록 페이지로 연결한다. `Sidebar.tsx`는 이미 `onNavigate` prop을, `App.tsx`의 모바일 메뉴는 이미 `navigate`를 지역 스코프에 갖고 있으므로, 이 두 곳의 "가이드" 링크는 기존 SPA 클라이언트 라우팅(`onNavigate`/`navigate`)을 그대로 재사용해 새로고침 없이 이동한다 — "관련 계산기" 링크(가이드 본문 안, `navigate`에 접근할 수 없는 위치)만 일반 `<a href>` 새로고침 링크로 처리한다.

## 검증 계획 — 이번 작업에서 가장 중요한 부분

가이드 콘텐츠는 계산기와 달리 "실행하면 정답이 나오는 코드"가 없다 — 세법·정책·금액은 실시간으로 바뀌고, 작성 시점(2026-07-30)이 모델 학습 시점 이후라 기억에 의존하면 오래되거나 틀린 정보를 "최신"인 것처럼 내보낼 위험이 크다. 따라서:

- **트랙2(정부지원금/청년정책) 각 글은 작성 전 반드시 웹 검색(WebSearch/WebFetch)으로 공식 출처(정부24, 복지로, 고용노동부, 국토교통부, 청년정책 관련 부처 홈페이지 등)를 직접 조회**한다. 기억이나 일반 상식으로 금액·자격요건·신청기한을 채우지 않는다.
- 검색으로도 특정 수치를 확정하지 못하면 그 수치를 추측해서 채우지 않고, "정확한 금액/조건은 [공식 사이트]에서 최신 공고를 확인하세요"로 명확히 비워둔다 — 틀린 숫자보다 빈 자리가 낫다.
- 각 가이드 본문 상단 또는 하단에 "최종 확인일: 2026-07-30" 같은 확인 날짜를 명시한다(기존 AboutPage의 "최근 업데이트" 관행과 동일).
- 각 가이드의 `sources` 필드에 실제로 웹 검색으로 확인한 공식 출처 URL을 넣는다(계산기 콘텐츠 심화 때와 같은 "최상위 홈페이지 URL, 확신 없으면 생략" 원칙 유지 — 다만 정책 정보는 구체적인 프로그램 페이지 링크가 사용자에게 훨씬 유용하므로, 이번엔 확인된 딥링크도 허용한다. 단 반드시 실제 방문·확인한 URL만 사용).
- **트랙1(계산기 확장판)** 도 절차·요건이 개정될 수 있으므로 동일하게 웹 검색으로 현재 시행 중인 내용을 재확인 후 작성한다(세율 자체는 이미 계산기 코드로 검증됐지만, "신고 절차", "준비 서류 목록" 같은 실무 정보는 코드에 없으므로 별도 확인이 필요하다).
- 구현 계획(다음 단계)에서 각 가이드 작성 태스크에 "웹 검색으로 확인한 사실" 목록을 태스크 완료 보고서에 남기도록 명시하고, 리뷰 단계에서 이 사실 확인 내역이 실제로 있었는지(단순 주장이 아니라 검색 결과 인용이 있는지) 별도로 검증한다.

## 스타일

계산기 페이지의 기존 톤(짧은 문단, `text-sm leading-relaxed text-slate-600`)과 앰버색 안내 상자 컨벤션을 그대로 따른다. 정책 정보는 "이 사이트는 참고용이며 정확한 신청은 공식 사이트를 확인하라"는 기존 면책 문구를 각 글에도 동일하게 적용한다.

## 범위 밖 (Out of scope)

- 가이드 전용 새 디자인 시스템/컴포넌트 라이브러리
- 가이드 간 연관 링크(가이드→가이드)
- 댓글, 좋아요 등 인터랙션 기능
- 가이드 검색(사이드바 검색과 별개) — 목록 페이지에서 트랙별로 나눠 보여주는 것으로 충분
- 향후 가이드 추가 시 자동화 스크립트(README 자동 갱신 같은) — 8편 규모에서는 수동 관리로 충분

## 검증 (빌드/구조)

- `npx tsc -b --noEmit`, `npm run build`, `npm run lint` 통과
- `dist/guides/index.html` 및 각 `dist/guides/<slug>/index.html`이 정상 생성되는지 확인
- 좌측 사이드바 아코디언에 "가이드" 그룹이 나타나지 않는지 확인 (groups.json 미포함 회귀 테스트)
- 각 가이드의 `sources` 링크가 실제 존재하는 공식 페이지인지 확인
