- 작성일: 2026-10-28
- 상태: **초안 3 — 2026-10-29 허브 5개 확정, 리디자인(에디토리얼 시안 A) 승인·반영, 문서 검토 대기** (승인 전까지 구현하지 않음)

- 범위: 1단계(구조). 2단계(신규 판단·비교 글)와 3단계(단순 계산기 정리)는 이 문서의 "후속 단계"에 방향만 적고, 각각 별도 승인 후 진행한다.

## 1. 배경과 목표

### 1.1 배경
- 애드센스 심사에서 8월에 세 번 "가치가 별로 없는 콘텐츠"로 거절됐고(2026-07-30, 08-11, 08-31), 2026-10-22 현재 사이트 상태는 "준비 중"이다. ads.txt 인식 문제는 10-22에 `vercel.json` 수정으로 대응했고 결과는 아직 확인 전이다.
- 지금까지 시도한 것: 계산기 콘텐츠 보강, 운영자·검증 방식 페이지, 가이드 신설과 확장(현재 16개), 저가치 페이지 `noindex`, 판정 배지, 내부 링크 정리, 법령 대조와 계산 정확도 수정(10월).
- 사용자 진단: 사이트가 "계산기 위주의 페이지"로 인식되어 통과하지 못하는 것 같다.
- 현재 구조가 주는 인상(사실 확인됨):
  - 홈 제목·H1: "연봉 실수령액·퇴직금·연말정산 계산기 모음"(2026-10-13에 홈을 허브로 바꾸며 설정)
  - `routes.json` 기준 계산기 46개, 가이드 16개(+가이드 목록), 용어사전, 정보, 게임
  - 사이드바·홈 목록의 중심이 계산기 카테고리

### 1.2 목표
1. 사이트의 첫인상과 정보 구조를 **"생활·금융 가이드 중심, 계산기는 보조 도구"**로 바꾼다.
2. 주제별로 가이드와 계산기가 한곳에 모이는 **주제 허브**를 만들어 주제 전문성이 드러나게 한다.
3. 기존 URL, 계산 로직, 법령 근거 내용은 바꾸지 않는다.

### 1.3 비목표 (이번 단계에서 하지 않는 것)
- 기존 URL 변경·삭제, 계산기 삭제, 리다이렉트 추가
- 현재 `noindex`(`/glossary`, `/yutnori`)의 변경
- 신규 가이드·비교 글 작성(2단계), 단순 수학 계산기 정리(3단계)
- 사이트 이름 변경: 이름은 "계산기"를 유지하고 부제만 추가한다(사용자 결정). 각 페이지 제목의 `| 계산기` 접미사도 유지한다.
- 애드센스 승인 보장. 승인 기준은 비공개이며, 이전 거절이 트래픽·사이트 연령 신호와 관련됐을 가능성은 이 설계로 해소되지 않는다.

### 2.2 결정 사항 (2026-10-29)
- `생활` 허브는 만들지 않는다. 허브는 `work`, `tax`, `property`, `support`, `finance` 5개.
- 남은 불균형: `support`는 계산기가 없고(교차 링크로 육아휴직급여·실업급여를 보여 준다), `finance`는 가이드가 없다. `finance`는 2단계 신규 글(대출 상환 방식 비교, DSR 이해 등)의 첫 대상으로 삼고, 그 전에는 개요 글과 도구 목록으로 구성한다.
- 이 설계는 허브 개수에 의존하지 않도록 `topics.json`으로 구동한다.

## 3. 설계 상세

### 3.1 데이터: `src/topics.json` (신규)
```json
[
  {
    "id": "work",
    "slug": "work",
    "label": "월급·직장",
    "path": "/topics/work",
    "summary": "한 줄 요약(카드용)",
    "members": ["salary", "unemploymentApplicationGuide"]
  }
]
```
- `members`는 `routes.json`의 `id` 목록이며 표시 순서를 정한다.
- 검증 스크립트 `scripts/check-topics.mjs`(신규): 모든 가이드·계산기 라우트가 정확히 한 주제에 속하는지, `members`에 존재하지 않는 id가 없는지 검사한다. 빌드 전에 사람이 실행하는 자체 확인용이며 새 계산기를 추가하면 갱신해야 한다는 점을 `CLAUDE.md`에 한 줄 추가한다.

### 3.2 주제 허브 페이지 (`/topics/<slug>`)
- 라우트: `routes.json`에 주제당 1항목(`id: topicWork` 등, `group: "주제"`). `group`은 메뉴 그룹이 아니므로 `groups.json`에는 넣지 않는다.
- 페이지 구성(위에서 아래):
  1. H1(주제명)과 **개요 글**: 그 주제에서 사람들이 겪는 상황, 이 사이트가 다루는 범위, 어떤 순서로 읽으면 되는지(고유 편집 문구, 600~900자 목표)
  2. **가이드 카드**: 제목, 한 줄 설명, 최종 업데이트 날짜
  3. **이 주제의 계산기**: 이름과 한 줄 설명 목록(링크)
  4. 관련 주제로 이동 링크
  5. 운영자·검증 방식 링크(기존 컴포넌트)
- 개요 글 작성 원칙: 법령 수치를 새로 쓰지 않는다. 이미 검증된 가이드 내용을 요약·연결하고, 숫자가 필요하면 해당 가이드 링크로 보낸다. 미확정 개편안은 언급하지 않는다(YMYL 정확성 위험 회피).
- 콘텐츠는 `pageContent.js`에 허브별 키로 둔다(`intro`, `faqs` 2~3개). 서버 HTML 프리렌더(`postbuild.mjs`)와 구조화 데이터(`CollectionPage`, `BreadcrumbList`)가 같은 소스를 쓴다. 허브 목록(가이드 카드·계산기 목록)은 `topics.json`과 `routes.json`에서 만들며, 홈·가이드 목록 페이지가 이미 쓰는 방식과 같다.

### 3.3 홈 (`/`)
- 제목: "생활·금융 가이드 — 월급·세금·부동산·대출 정리와 계산기 | 계산기"(60자 이내로 조정)
- H1: "생활·금융 가이드와 계산기"
- 구성:
  1. 한 단락 소개(누구를 위한 사이트인지, 공식 자료로 검증하고 수정 이력을 공개한다는 점)
  2. **주제 카드 5개**(주제명, 요약, 가이드 N개·계산기 N개)
  3. **최근 업데이트된 가이드** 5개(기존 `changelog` 데이터 재사용)
  4. **많이 쓰는 계산기** 소수(`popularLinks.json` 재사용, 현재 10개 → 6~8개로 축소)
  5. 운영자와 검증 방식 소개(기존 블록 유지)
- 현재 홈의 "카테고리별 계산기 46개 목록"은 제거한다. 계산기 전체 목록은 상단 "도구" 패널과 사이트맵에 남는다.
- 서버 HTML(`postbuild.mjs`의 홈 블록)과 `HomePage.tsx`를 같은 구성으로 맞춘다.

### 3.4 메뉴 (상단 내비게이션으로 대체)
- 데스크톱 사이드바를 없애고 상단 마스트헤드 내비게이션으로 통일한다: `홈 · 세금 · 월급·직장 · 부동산 · 정부지원·청년 · 대출·금융 · 도구 ▾` (가이드 전체 목록은 홈과 각 허브에서 제공).
- **도구 ▾**: 클릭 시 열리는 패널. 5열(월급·직장 / 세금 / 부동산 / 대출·금융 / 생활)로 계산기 전체를 보여 주고, 상단에 이름 검색칸을 둔다. 일반 계산기는 생활 열 맨 위에 강조. 기존 `Sidebar.tsx`의 검색·그룹 로직을 재사용한다.
- 모바일: 햄버거 → 전체 화면 메뉴(홈, 주제 5개, 도구 접이식).
- 현재 페이지가 속한 주제는 내비게이션에서 밑줄(강조색)로 표시한다.
- 정보 링크(소개·검증 방식·개인정보처리방침)는 기존대로 푸터에 둔다.

### 3.5 사이트 성격 문구
- 대상: 헤더 한 줄 설명(`App.tsx`), 홈 메타 설명, `og:description`(`index.html` 기본값 포함), 소개 페이지 `about.intro`, `public/llms.txt` 서두
- 문구 방향: "생활·금융 가이드와 계산기". 이름과 로고는 유지.
- 계산기 페이지의 제목·설명은 바꾸지 않는다(검색 노출 유지).

### 3.6 SEO·프리렌더
- 사이트맵: 주제 허브 5개 추가(`lastmod`는 개요 글 수정일 — `pageContent`의 `updatedAt` 사용).
- `postbuild.mjs`: `topic*` 라우트용 프리렌더(개요 글, 가이드 카드, 계산기 목록, 구조화 데이터)와 홈 블록 교체.
- 내부 링크: 가이드 ↔ 주제 허브 ↔ 계산기가 양방향으로 연결되도록 가이드 본문 하단 "이 주제의 다른 글" 링크는 2단계에서 검토(1단계는 허브 → 구성원 링크와 breadcrumb까지).
- `groups.json`·`popularLinks.json`·`routes.json`의 기존 계약은 유지한다.

| 광고 | `AdSlot` 위치·정책은 유지(본문 사이·하단). 새 레이아웃에서 콘텐츠를 밀어내지 않도록 높이를 미리 확보 |

**구현 방식**: Tailwind v4 `@theme` 토큰(`--color-paper` 등)과 글꼴 변수를 `index.css`에 정의하고 공용 컴포넌트(`ui.tsx`의 Field/Row/Card 등, `InfoSection`, `GuideArticlePage`, 마스트헤드)를 먼저 바꾼다. 개별 페이지의 `slate-*`·`emerald-*` 클래스(약 62개 파일)는 공용 컴포넌트 변경으로 대부분 해결하고, 남은 것은 파일별로 점검한다. 윷놀이(`game` 그룹)는 전체 폭 게임 화면이라 토큰만 적용하고 레이아웃은 건드리지 않는다.

**글꼴 로딩**: Google Fonts CSS(`display=swap`, `preconnect`)로 시작한다. 한글 웹폰트는 유니코드 범위로 분할 제공되어 필요한 조각만 받는다. 기준: 모바일 LCP 악화 없음, CLS 0.1 미만. 빌드 후 측정해 기준을 넘으면 자체 호스팅(서브셋)으로 전환한다. 기본 글꼴 대체 목록은 `Pretendard`·`Apple SD Gothic Neo`·`Malgun Gothic`.

**접근성·성능 점검**: 키보드로 도구 메뉴 열기·닫기(Esc), 포커스 링 유지, `prefers-reduced-motion` 존중, 모바일 폭 360px에서 가로 스크롤 없음, 터치 영역 44px 이상.

## 4. 검증 계획
1. `node scripts/check-topics.mjs` — 모든 가이드·계산기 전수 배정, 중복·누락 0
2. `npm run build` 및 `npx tsc -b` 통과
3. 전체 페이지 서버 렌더링(기존 방식의 smoke)으로 `NaN`·`undefined` 없음 확인, 허브 페이지 렌더링 확인
4. 사이트맵 URL 수 증가분(허브) 확인, 기존 URL 전부 유지 확인(빌드 전후 비교)
5. 브라우저 확인(Playwright 스크린샷, 360·768·1280px): 상단 내비·도구 패널·모바일 메뉴, 허브·홈 링크 이동, 키보드 조작, 가로 스크롤 없음
5-1. 대표 페이지(홈·허브·가이드·계산기 5종·윷놀이) 전후 스크린샷 비교, 글꼴 로딩 후 CLS·LCP 측정
5-2. 프리렌더(JS 미실행) HTML도 본문 가독성 유지 확인
6. 내부 링크 깨짐 검사(`dist/**/index.html`의 href 전수)
7. 구조화 데이터(CollectionPage, BreadcrumbList) 존재 확인
8. 배포 후 확인(홈 제목·H1, 허브 200, 사이트맵, `llms.txt`)

## 5. 롤아웃과 롤백
- 한 브랜치에서 작업하고 검증을 마친 뒤 사용자 승인 후 `main`에 푸시한다(배포는 Vercel 자동).
- 롤백: 해당 커밋 되돌리기로 홈·메뉴·허브가 이전 상태로 돌아간다. URL을 바꾸지 않았으므로 리다이렉트 정리는 필요 없다.
- 색인 요청: 배포 후 Search Console에서 홈과 허브 URL을 색인 생성 요청하고 사이트맵을 다시 제출한다.

## 7. 후속 단계 (이 문서의 승인 범위 밖)
- **2단계 — 판단·비교 가이드**: 계산기 여러 개를 엮는 글을 소수(3~5편) 작성한다. 후보: 전세 vs 월세, 1주택 vs 다주택 보유세, 대출 상환 방식 비교와 DSR 이해(`finance` 허브용), 연봉 협상 시 실수령액 보는 법. 법령·수치 대조와 "상황에 따라 다르다"는 단서 처리를 필수로 한다. 글마다 별도 선정·승인.
- **3단계 — 단순 수학 계산기 정리**: 나이·날짜·BMI 등 가이드 연결이 없는 계산기의 색인 대상 여부를 검토한다. 기존 URL에 영향이 있으므로 별도 설계·승인 후 진행한다.
